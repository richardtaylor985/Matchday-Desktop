# Matchday Desktop 3.2 RC3

RC3 replaces the previous wallpaper PID-only lifecycle with authoritative ownership.

## Wallpaper ownership
Each active Dynamic Wallpaper worker owns:
- PID
- random 48-character ownership token
- start timestamp
- executable path

The ownership record lives in native Matchday configuration.

Before every wallpaper capture and before scheduling each future refresh, the worker
must prove that its PID + token still match the authoritative ownership record.
A stale worker cancels its timers and exits.

## Renderer safety
Before every capture, Matchday compares the native selected club with the hidden
renderer club. A mismatch can never be captured. The renderer is reloaded from the
native selected club first.

## Hibernate/resume
A worker waking from hibernate may only resume if it still owns the authoritative
token. Otherwise it exits immediately.

## Diagnostics / memory
Structured wallpaper lifecycle logging remains enabled.
Wallpaper worker memory usage is sampled every five minutes.

## Regression test
1. Coventry selected, Dynamic Wallpaper enabled.
2. Hibernate Windows.
3. Resume.
4. Change to Arsenal and Save.
5. Leave running for at least 10 minutes.
6. Wallpaper must remain Arsenal through repeated refresh cycles.
7. Repeat Arsenal -> Coventry.
8. Inspect live-desktop.log for at most one active ownership token.
